# CLAUDE.md — Sour Platinum

This repo is **Sour Platinum**, SourApple's Pokémon Platinum (US, Rev 1) ROM hack, rebuilt on
top of the [pret/pokeplatinum](https://github.com/pret/pokeplatinum) decompilation. The hack
was first made by editing a ROM with external tools. It was then converted back into decomp
source: JSON data, text banks, field scripts, PNG graphics and C. **Make every change in
source.** Never hex-edit the built ROM.

- Player-facing changelog and the list of intentional differences from the original ROM:
  `sourplatinum/README.md`. Read it before changing anything it lists.
- Upstream base: pret/pokeplatinum commit `fe1ea418`. The Sour Platinum commits sit on top of it.
- Upstream decomp docs still apply: `INSTALL.md`, `CONTRIBUTING.md`, `docs/`.

## Build

- Set up the toolchain as in `INSTALL.md` (Linux/WSL2/MSYS2/macOS), then run `make`.
  Output: `build/pokeplatinum.us.nds`.
- `make` no longer checks against the retail SHA1 (`all: release` in the Makefile). Don't
  re-add `check`, because the hack can never match retail. `make check` will always fail.
- The first build downloads meson subprojects. If a network proxy blocks GitHub tarball or
  wrapdb downloads (rapidjson, yyjson), clone those projects with git into
  `subprojects/rapidjson-1.1.0` and `subprojects/yyjson-0.12.0`. Copy in the wrapdb
  `meson.build` files and apply the `diff_files` patches listed in the `.wrap` files. Meson uses
  an existing directory as-is.
- Reference hash: when this file was written, a clean clone built to SHA1
  `4e4dbedd6c453e806cb5980a44d6208f957bf9cb`. It changes with any edit; it's only useful for
  checking that an untouched checkout builds reproducibly.

Hack-specific details worth knowing:

- **Linking Cord** replaces the Loot Sack. The constant is `ITEM_LINKING_CORD`, renamed in
  `generated/items.txt`, and the files are `linking_cord.*`. It is an evolution item
  (`ITEM_USE_FUNC_EVO_STONE`). Its ID is above `ITEM_TM01`, so the Veilstone prize exchange
  script branches on it explicitly to skip the TM confirmation text.
- **Trade-evolution items** (King's Rock, Metal Coat, etc.) use `ITEM_USE_FUNC_EVO_STONE` with
  `"itemUseParams": {}`, and the matching species evolve via `EVO_USE_ITEM`. Species that
  evolved by plain trade keep `EVO_TRADE` and gain an `EVO_USE_ITEM` entry for the Linking Cord.
- **Honey trees**: each honey tree map has bg events whose `"script"` is the 1-based index of
  the `ScriptEntry` `<Map>_HoneyTree` in that map's script file. That script is appended last, so
  keep it last or update the event's script number. The species table is in
  `<Map>_HoneyTreePickSpecies` and the level is in `StartLegendaryBattle VAR_0x8004, 12`. The 20
  copies are identical except for labels and message IDs.
- **Unown** has separate files for the species icon (`unown/icon.png`) and the form-A icon
  (`unown/forms/a/icon.png`, wired via `unown_a_icon` in `res/pokemon/unown/meson.build`). The
  original hack gave them different art.
- **Metang** has female sprites even though it is genderless. They are kept for fidelity but the
  game never shows them.

## Generated vs. hand-edited text

`pl_msg.narc` is built from `res/text/*.json` **plus** banks generated by tools. Don't edit or
create these banks in `res/text/`. Edit their sources instead:

- species names, Pokédex entries, categories, heights/weights → `res/pokemon/*/data.json`
  (`tools/dataproc/src/speciesproc.c`)
- item names, plurals, articles, descriptions → `res/items/data/*.json`
- move names and descriptions → `res/moves/*/data.json`
- NPC/frontier trainer names and messages → `res/trainers/...`
- town map text → `res/town_map/town_map_data.json`

The full list is `generated_text_banks` in `res/text/meson.build`. Scripts refer to messages by
ID through headers generated into `build/res/text/bank/<bank>.h`. When adding messages, append
them with a descriptive ID such as `Route206_Text_HoneyTreeSweetScent`.

## JSON formatting

The JSON files are hand-formatted, and the house style differs by directory. Keep it when
editing so diffs stay small:

- `res/pokemon/*/data.json`: 4-space indent, trailing newline, empty lists as `[  ]`. Arrays are
  inline for `types`, `egg_groups`, `abilities`, each `by_level` entry, two-element evolution
  and `icon_palette` entries, and any single-scalar list.
- `res/moves/*/data.json`, `res/pokemon/*/sprite_data.json`: 4 spaces, never inline, empty lists
  `[]`, **no** trailing newline.
- `res/items/data/*.json`: 2 spaces, never inline, empty `[]`, no trailing newline.
- `res/text/*.json`: 2 spaces (`json.dumps(indent=2, ensure_ascii=False)`).
- `res/field/events/*.json`, `res/field/encounters/*.json`: 4 spaces, never inline.

`sourplatinum/tools/jfmt.py` reproduces these styles. Edit by hand or round-trip with it. Don't
reformat whole files with a generic formatter.

## Graphics with nitrogfx

`build/tools/nitrogfx/nitrogfx` converts in both directions. These commands were verified to
round-trip byte-for-byte:

- Pokémon battle sprite: `nitrogfx X.NCGR out.png -palette normal.NCLR -scanfronttoback`.
  This also writes `out.png.key`. Rebuild with `-encodefronttoback -scan`. Keep the `.key` next to
  the PNG.
- Pokémon icon: `nitrogfx X.NCGR icon.png -palette shared.NCLR -width 4 -palindex <icon_palette+1>`.
- Palettes: `nitrogfx X.NCLR out.pal`. Battle palettes rebuild with
  `-bitdepth 8 -nopad -comp 10`.
- Trainer encounter mugshot (cell graphic): decode with `-cell <mugshot_cell NCER>`, then save the
  PNG as **8-bit with the full 256-entry palette**. A 16-colour PNG re-encodes wrongly.
- Item icon: 32×32 PNG (`-width 4`) plus a 256-entry JASC `.pal`. Only the first 16 colours are used.

## Verifying against the original ROM

The original ROM isn't in the repo. Ask SourApple for `Pokemon SourPlatinum.nds`
(SHA1 `115a0047f1c9654f479b8397f1663006bebbe569`) if you need it. Tools in
`sourplatinum/tools/` need Python 3 with `ndspy` and `Pillow`:

- `verify.py BUILT.nds ORIGINAL.nds` lists every remaining difference, ignoring padding and
  header-only noise. Expected output after the conversion is only:
  `zukan_enc_platinum.narc` (Pokédex areas regenerated from the new encounters), `scr_seq.narc`
  (script layout only), `pl_msg.narc` members 393/413/706/707/709/718 (see below) and
  `pl_poke_icon.narc` members 547–550 (4 unused icons, kept in `sourplatinum/unused_icons/`).
- `cmptext.py BUILT.nds ORIGINAL.nds build/res/text/text_banks.order` compares decrypted text.
  Expected: only `species_name_with_articles`, `species_weight` and `species_height` differ.
  These are intentional fixes for mistakes made by the original editing tool.
- `scrdis.py` (with `REPO=` set) disassembles field scripts. `Script.canon()` compares scripts
  regardless of layout. It was used to confirm every changed script matches the original logic.
- `romdiff.py`, `extract.py`, `sym.py` (address → symbol via `build/main.nef.xMAP`) and
  `gen4msg.py` (text bank decryption) are lower-level helpers.

## Not yet done / caveats

- The rebuilt ROM hasn't been playtested in an emulator. It was only verified against the
  original data and code. Good things to check first: a honey tree battle, buying the Linking
  Cord, teaching a TM twice, and using a trade-evolution item.
- Hidden Power is fixed at 60 only in the battle script command (`BtlCmd_CalcHiddenPowerParams`),
  matching the original hack. Other places that may compute Hidden Power's power weren't checked.
- Pret's repo isn't configured as a remote. To get decomp updates:
  `git remote add upstream https://github.com/pret/pokeplatinum` then `git pull upstream main`.
